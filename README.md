# 今日の予約状況を、Instagramのストーリーに毎朝自動で投稿する

予約システムの「今日の予約状況」を、毎朝、おしゃれな画像にして、Instagramのストーリーに自動投稿します。
休診日には「本日は休診日です」と次の診療日を出します。時間ごとの予約状況に、**オプションの予約状況（オプション名と、60分のオプションが次の枠まで続くことを示す↓）**も載せられます。氏名などの個人情報は一切載せません。

## 全体の流れ

```
毎朝 6:17（日本時間）
 GitHub Actions ─① 予約システム(Apps Script)から今日の空き状況を取得
               ─② 画像（1080×1920のJPEG）を作る
               ─③ 画像をリポジトリに保存（＝公開URLができる）
               ─④ Apps Script に「このURLの画像を投稿して」と依頼
 Apps Script  ─⑤ Instagramに投稿（トークンの管理・更新、失敗時のメール通知もここ）
```

- 費用：すべて無料です（GitHubは公開リポジトリなら無料、Apps Script・InstagramのAPIも無料）。
- 画像に載るのは、時間ごとの ◯（空きあり）△（残りわずか）×（満席）と、オプション名だけです。
- 60分のオプションは、使い始める枠にオプション名、次の枠に「↓」が出ます（その枠もオプションが使用中という意味です）。同じ枠に同じオプションが2件あれば「トレーニング×2」と出ます。
- 診療時間・休診日・特別営業日・受付人数・枠ごとの人数指定は、予約システムの設定がそのまま反映されます。

## できないこと（Instagramの仕様）
- ストーリーに、リンクスタンプ・メンションスタンプ・投票などは付けられません（画像の中の文字として、アカウント名を載せます）。
- 個人アカウントでは使えません（ビジネスアカウントが必要。すでに該当しています）。

## 準備の手順

### 1. Meta（Facebook）の開発者設定で、投稿用のトークンを作る

アプリを作り、ユースケース「Instagramでメッセージとコンテンツを管理」を選んだあとの手順です（アプリの「公開」や審査は不要です）。

**① 自分のInstagramアカウントを「Instagramテスター」として追加する**
1. 左のメニューの「アプリの役割」を開き、「役割」を選びます。
2. 「ユーザーを追加（メンバーを追加）」を押し、「Instagramテスター」を選びます。
3. 投稿に使うInstagramのユーザー名（@は除く）を入力して追加します。
4. Instagram側に招待が届くので、承認します。Instagramのパソコン版（instagram.com）で、設定の「アプリとウェブサイト」にある「テスターの招待」を開いて承認します。メニュー名は変わることがあります。

**② ユースケースの権限を確認する**
1. ダッシュボードに戻り、一番上の「『Instagramでメッセージとコンテンツを管理』ユースケースをカスタマイズ」を開きます。
2. 権限の一覧に、`instagram_business_basic` と `instagram_business_content_publish` があることを確認します。`instagram_business_content_publish` がなければ、「追加」を押します。

**③ トークンを生成する**
1. 同じ画面の「アクセストークンを生成する」の欄で、①で追加したアカウントが表示されていることを確認します。
2. 「トークンを生成」を押し、Instagramにログインして、表示される権限をすべて許可します。
3. 表示されたアクセストークンをコピーします。有効期間（約60日）の表示があるか確認してください。トークンはパスワードと同じ扱いです。人に見せたり、チャットや画像に貼ったりしないでください。
4. 同じ画面に、アカウントのIDが表示されていれば、メモします（なくても構いません。次の手順で空欄にできます）。

**④ トークンが使えるか確認する**
ブラウザのアドレス欄に、次のURLの `ここにトークン` をトークンに置き換えて貼り付け、開きます。

`https://graph.instagram.com/v23.0/me?fields=username,account_type&access_token=ここにトークン`

`username` に投稿したいアカウント名、`account_type` に `BUSINESS` と出れば成功です（ストーリーの自動投稿は、ビジネスアカウントのみ可能です）。エラーが出る場合は、内容を教えてください。

### 2. Apps Script（Code.gs）の設定

1. 最新の `Code.gs` を貼り替えます。
2. 「プロジェクトの設定」→「スクリプト プロパティ」に、次の4つを追加します。

| プロパティ | 値 |
|---|---|
| `IG_ACCESS_TOKEN` | 手順1でメモした長期アクセストークン |
| `IG_USER_ID` | 手順1③でメモしたアカウントのID（**空欄でも動きます**。その場合は、トークンの持ち主のアカウントを自動で使います） |
| `STORY_PUSH_SECRET` | 長めの合言葉（自分で考えた英数字。手順3の `STORY_SECRET` と同じにします） |
| `STORY_IMAGE_PREFIX` | `https://raw.githubusercontent.com/ユーザー名/リポジトリ名/`（手順3で決めた名前。末尾の `/` まで入れます） |

   （`STAFF_EMAIL` が未設定なら、失敗した時のお知らせメールを受け取るために、ここで設定してください）
3. 「デプロイを管理」→ 鉛筆アイコン →「新バージョン」で更新します。
4. 「トリガー」に、次の2つを追加します。
   - `refreshInstagramToken` … 時間主導型・**月ベースのタイマー**（毎月1日など）。トークンの期限切れを防ぎます。
   - `checkStoryPosted` … 時間主導型・**日付ベースのタイマー**・午前7時〜8時。その日のストーリーが投稿できていなければ、メールで知らせます。

### 3. GitHub に、画像づくりの場所を作る

1. https://github.com/ でアカウントを作り、「New repository」でリポジトリを作ります（例：`kohmura-story`）。
   - **Public（公開）** にします。画像を公開URLで見られるようにするためです（画像には、予約状況の◯△×しか載りません）。
   - 作成後の画面で、リポジトリ名の近くに「Private」と出ていないか確認します。「Private」なら、「Settings」→ 一番下の「Danger Zone」→「Change visibility」で Public に変えます。

2. **ファイルを2つアップロードします。** リポジトリの画面の「uploading an existing file」のリンク（または「Add file」→「Upload files」）を押し、`story.html` と `make_story.py` の2つを、画面にドラッグします（フォルダごとではなく、ファイルを2つ選んでドラッグします）。下の「Commit changes」を押して保存します。

3. **自動実行の設定ファイルを、画面上で作ります。** `.github` フォルダは、パソコンでは見えない隠しフォルダなので、ドラッグではなく、次の方法で作ります。
   - 「Add file」→「Create new file」を押します。
   - 上の名前の欄に、`.github/workflows/story.yml` と入力します（`/` を打つと、フォルダが自動で作られます）。
   - 大きな入力欄に、`story.yml` の中身を、全部貼り付けます。
   - 右上の「Commit changes」→「Commit changes」で保存します。

4. リポジトリの「Settings」→「Secrets and variables」→「Actions」を開き、**Secrets**（New repository secret）に3つ登録します。

| 名前 | 値 |
|---|---|
| `API_URL` | 予約システムのApps ScriptのURL（`.../exec`。予約ページの `API_URL` と同じもの） |
| `SITE_URL` | 予約ページの公開URL（例 `https://xxxx.pages.dev`。末尾の `/` なし） |
| `STORY_SECRET` | 手順2の `STORY_PUSH_SECRET` と同じ合言葉 |

5. 同じ画面の **Variables** タブに、見た目の設定を登録します（なくても動きます）。

| 名前 | 内容 | 例 |
|---|---|---|
| `STORY_THEME` | （通常は不要）配色。スタッフページで配色を選んでいれば、そちらが優先されます。スタッフページで未設定のときだけ使われ、これも無ければ `milk` です | |
| `STORY_HANDLE` | 画像に載せるアカウント名 | `@koumura_b.c` |
| `STORY_NOTE` | 毎日出したい一言（任意） | `トレーニングのご予約も承ります` |
| `STORY_CTA` | 案内文（任意。既定は「ご予約はプロフィールのリンクから」） | |

6. 「Settings」→「Actions」→「General」→ 一番下の「Workflow permissions」が、「Read and write permissions」になっていることを確認します（違う場合は変更して「Save」）。

### 4. テスト

1. リポジトリの「Actions」タブ →「instagram-story」→「Run workflow」を開きます。
2. **まず `skip_post` を `true`** にして実行します。画像を作るだけで、Instagramには投稿しません。
   数分後、リポジトリの `stories` フォルダに `story-日付.jpg` ができるので、見た目を確認してください。
3. 問題なければ、`skip_post` を `false`（または空欄）にして、もう一度実行します。Instagramのストーリーに投稿されます。
   同じ日に2回実行しても、2回目は「投稿済み」としてスキップされます（二重投稿は起きません）。
4. 翌朝からは、自動で毎朝投稿されます。

## スタッフページでの設定

- **画像の配色**：「メニュー管理」タブの下の「Instagramストーリーの見た目」で、ミルク（明るい）・青緑・夕焼けから選べます。選んだ配色は、次の朝の投稿から使われます。
- **ストーリーに載せるオプション**：「メニュー管理」タブの「オプションの管理」で、オプションごとに「ストーリーに載せる／載せない」を選べます。「載せない」にしたオプションは、予約があっても画像に出ません。
- どちらも、Code.gs（Apps Script）を最新にして「新バージョン」でデプロイしておく必要があります。

## 毎日の運用

- 一言（`STORY_NOTE`）や案内文を変えたい時は、GitHubの Variables を書き換えます。
- 受付人数・休診日などを予約システムで変えると、次の朝の画像にそのまま反映されます。
- 失敗した場合は、`STAFF_EMAIL` にメールが届きます。GitHubからも失敗のお知らせが届きます。手動で投稿するか、原因を直して「Run workflow」で再実行してください。
- 画像は7日分だけ残り、古いものは自動で削除されます。

## うまくいかない時

| 症状 | 確認すること |
|---|---|
| 朝になっても投稿されない | GitHubの Actions タブで、実行が赤（失敗）になっていないか。長く更新がないと、GitHubが定期実行を止めることがあります。その場合は、Actions タブで再び有効にしてください |
| 「画像が公開URLで見られません」 | リポジトリが Public か。`STORY_IMAGE_PREFIX` のユーザー名・リポジトリ名が合っているか |
| 「画像のURLが許可されていません」 | `STORY_IMAGE_PREFIX` の末尾が `/` で終わっているか。URLの綴りが合っているか |
| 「unauthorized」 | `STORY_SECRET`（GitHub）と `STORY_PUSH_SECRET`（Apps Script）が同じか |
| Instagramの権限・トークンのエラー | トークンの期限切れや、権限不足の可能性があります。手順1でトークンを作り直し、`IG_ACCESS_TOKEN` を書き換えます |
| 「Apps Scriptの応答がJSONではありません」 | Code.gsを貼り替えたあと、「新バージョン」でデプロイしたか |
| 年が変わって、祝日がずれる | 祝日一覧は、予約システムの `common.js` と `Code.gs` の中にあります。年が変わる前に、追記してください |
